# Grok 长视频 skills 交付说明

版本：v0.1，实验版。能力核验日：2026-10-02。

本次交付三份相互联通的skill：首次生成、诊断修复、闭环编排。每份阅读文件均可独立下载完整Markdown，也可导出精简SKILL.md和参考文件。首次测试建议三个一起交给执行者，主入口使用闭环编排；它按实际任务读取首次生成或修复规则。

## 1. 本次整理的判断

Grok适合探索优秀长视频项目，但“长视频”首先是全片叙事、角色资源、生成片段与时间线形成整体，不等于连续调用一个端点就能无限延长。本套方法让它在适合的段落自主生成，在身份、道具、因果和接缝关键点加视觉条件，出现问题时只修需要修的范围。

我保留了你上传蓝本的全片规划、锚点卡、分镜表、提示词按模式编译、候选管理、15维审查、失败归因和回归；加入此前讨论中明确的根帧修正、组内再锚定、真假尾帧接续、正常切镜、合格双端桥接、终态偏离、正式选片和下游版本处理。Grok新增能力用作可测试选项，而不是未经验证的默认万能流程。

本次上传的正文自称“通用版、不绑定具体模型”。因此我按你已测试有效的长视频制作蓝本迁移制作方法，没有把其所有参数、种子或负面词规则认定为Seedance 2.5或Grok的官方接口事实。之前的具体生图配方和视频案例只在已知适用范围内保留；没有拿不到的旧文件内容补出新规则。

## 2. 三份skill的分工

| 文件 | 正式名称 | 负责什么 | 与其他两份的联系 |
|---|---|---|---|
| GROK_01_CREATE.html | grok-long-video-create | 全片先规划；锚点/分镜；实际输入模式；生成候选 | 发现偏差交修复；大偏离重建可回到它 |
| GROK_02_REPAIR.html | grok-video-repair | 找最早坏点；大/小偏离；编辑、窗口或根帧修复；必要下游 | 重建交首次生成；结果交编排 |
| GROK_03_ORCHESTRATE.html | grok-video-orchestrate | 调度全片制作、质检、修复、选片、成片和测试 | 读取另两份，使用同一GLV/1.0协议 |

这三个是规则模块，不是要求你增加三个Agent。现有一个Agent可顺序读取，也可分别绑定现有专业Agent。接口仍沿用你项目的canonical、OCC、receipt、锁与审批，不要求修改正在制作的前端页面。

每份本体都配有相同版本的共享协议和能力档；三份副本内容/hash一致。规则通过项目对象ID、资产版本与SkillHandoff连接，不依赖易变化的本机路径。

## 3. 修复部分的核心变化

**小偏离：依据正确，主要内容值得保留，缺陷能界定。** 优先选择最小有效修法：剪辑/调色/声音，合理再采样，针对性prompt修正，合法短片编辑，合格双端窗口重生。哪个先做由问题决定，不是固定跑完所有步骤。

**大偏离：根图、身份、场景状态或故事因果已经错误，持续漂移，或局部修补不能保住硬条件。** 从最早坏点重建必要范围：修正确根图、生成新视频、正式选片后再查真正依赖它的下游。保留独立而合格的镜头。

严重度与范围分开：半秒换脸是严重问题，也可能只需局部修；整镜轻微偏色可能后期即可。没有“坏帧不到X%就通过”或“整镜受影响就全片重生”的规则。

两个此前特别有用的方法保留了：

- **先修正确根帧，再视频，再真实尾帧接力。** 不传播坏根；生图里的Look要进入真实请求。
- **组内也要再锚定。** 远景转近景、遮挡后重现、身份特征不足等都可能触发，不只给新组首镜加Look，也不设固定每几镜重置。

终态偏离单独处理，例如“接近水面”变“已经触水”，不能仅因为画面好看就让候选改写故事。正常切镜保留；错误端点先修；桥接只为真正的叙事/视觉连接问题服务。

## 4. 与你提供的Grok参数相比，核验后需要调整什么

以下官方能力来自配套能力档的一手来源，具体账户/第三方平台仍须验证。

| 需要关注的点 | 文件如何处理 |
|---|---|
| 1.5支持首帧和独立参考组合 | 可以测试原生“正确尾帧作image＋Look作reference”，不用一律先融合图 |
| 组合不再是纯i2v | 按reference路径最高720p规划；不能同时承诺纯i2v的原生1080p |
| 内部关键帧最多4个 | 时间严格在片内、采用合法1/3秒网格；端点用image/last_frame |
| 参考标签从0开始 | 有首帧时IMAGE_0属于首帧，Look从IMAGE_1开始 |
| 编辑与延长的示例使用经典模型 | 独立保存路径的model/endpoint；不把1.5高级生成功能算作同一编辑端点能力 |
| 延长输入最长15秒 | 完整返回片超过15秒后不能无限重投，改合法末窗或分段首帧生成 |
| 延长返回整片 | 成片只加入确认的新内容，防源片重复和时长算错 |
| 原生编辑源最长8.7秒、最高720p | 长片必须合理截窗或另选修法；无时间mask/像素无损承诺 |
| 自有声音权限 | 预设voice_id与任意声音文件、背景音乐续接分别判断 |
| seed/fps/negative_prompt | 本次所查指南未确认可设置，默认不发送；候选用request_id记录 |
| “源片50MB” | 保留为用户提供的渠道限制，未当成所有官方延长路径通用限制 |
| 文生先有隐藏中间图 | 未找到足以确认内部机制的官方依据，流程不依赖或宣称已拿到该图 |

能力更多不能直接支持“完胜”的视觉质量判断。本次不对Agnes或Seedance的现行能力另作排名；只为你正在测试的Grok设计适合的方法。

## 5. 下载与使用

打开三个HTML文件，分别选择“下载完整Markdown”。它们内含各自本体和需要的共享资料，是三个可独立交给zcode的完整文件；不需要网络脚本，下载不会执行视频生成。

若你采用标准skill目录结构，在文件内的“标准文件”区域逐一下载SKILL.md、agents/openai.yaml和references文件，并按显示路径放置。标准本体很短，参考按需读取；完整Markdown适合这轮人工阅读、转交和外部测试。

先读本说明，再把三份完整Markdown给一个**与正在做前端的zcode任务分开的测试会话**。主入口是整合编排；只修已有视频时可直接从修复进入。完整Markdown内部保留同一协议，所以不是三套互相竞争的规则。

你可以直接给测试执行者这段任务：

```text
请读取我提供的Grok首次生成、诊断修复、闭环编排三份skill及其GLV/1.0协议，以闭环编排为主入口进行本轮测试。

本轮主要探索Grok视频制作效果，不修改正在进行的工作流前端，不覆盖现有Agnes/Seedance正式规则。先核对我的测试渠道、实际model/endpoint和适配器字段，保留documented、user_reported、adapter_verified、visually_accepted的区别。

使用一个新故事先规划全片，再设计生成单元；不要逐镜照抄旧答案，也不要默认全部融合首图或全部原生extend。重点检验正确尾帧＋批准Look的原生组合、组内远景转近景再锚定、道具/终态控制，以及小偏离保片修补和大偏离根帧重建。

费用不是主要限制。每次真实生成要回答明确问题，保存事前决策、compiled request、request_id、候选和真实帧来源；先形成候选和可播放粗剪，再由我观看选择。不支持的路径显式降级，不虚构能力或回执。

冻结本轮skill与素材版本；发现规则问题先记证据，不把修改前后算同一次盲测。报告用户所见问题、首个偏离点、选择修法、保留素材、依赖处理、整段回归和仍未验证的假设。没有视频工具时先交plan_only和合法调用草案，不能声称完成真机测试。
```

## 6. 先测什么，之后怎么改

第一轮先做四类高价值问题：远景转近景身份、道具动作与终态、小偏离窗口修复、大偏离根图重建。随后再测长镜头延长、跨空间、桥接、声音。每条路径保失败候选，不只展示最好的一条。

同条件比较用于归因；不同模型各走最适合自己的流程用于比较最终工程效果。二者都可以做，但结论分开。若同时改变模型、规划、参考和时长，只能说新组合更好，不能单独证明某一项有效。

你回传时最有帮助的是：原版/候选视频、问题时间码、批准Look和道具、真实请求、路径与时长、用户最后保留哪个、修改是否影响下游。你只需看片指出感受，执行者负责整理技术证据。

## 7. 本次验证及边界

已完成三份frontmatter、名称、相对引用、JSON示例和共享副本一致性检查。另以独立会话检验了：12秒片局部换脸且要求1080p；18秒好片延长8秒但渠道不支持首帧＋Look，以及候选未选片、独立下游与逐镜BGM的处理。

这些情景用于检查决策能否从规则推导出来，不代表Grok画面已通过。未调用Grok视频生成/编辑接口，没有对你真实项目的canonical、视频选片、代码或旧skill作修改。

因此这套交付的准确定位是**可以开始系统性试验的v0.1**，还不是已真机封板的生产保证。你逐轮看片后，把有反例和适用范围的配方升级；这样才能形成你想要的、真正针对Grok的优秀skills。
