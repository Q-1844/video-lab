# Grok 视频诊断与修复

执行版本 v0.1；优先修最早错误依据，保留有价值素材；不承诺生成式编辑保留其他像素或声音。

## 1. 读取证据并冻结合格部分

先读 [共享协议](#glv-shared) 与 [能力档](#glv-capabilities)，再读 [修复手册](#glv-method)。接受ShotPlan、批准锚点、候选/选片版本、用户反馈、实际请求、来源帧和依赖图。

输出RepairTicket、修复前后候选、实际回执、原问题及回归检查、正式选片所需材料、下游复核清单。没有真实视频时只做有条件诊断，列出证据缺口；不能把文字描述推测成亲眼看到的坏帧。

先列 `keep`（合格且应保留）、`repair`（确需处理）、`uncertain`（待补证据）。冻结正确Look、关键道具、故事因果、已选镜头及不依赖坏点的分支；新候选不能覆盖旧版本。

## 2. 找到首个偏离点

沿因果顺序检查：批准资产 → 实际参考绑定 → 根帧 → 首帧 → 运动过程 → 尾态 → 下游起镜 → 时间线/声音。

对每个问题记录：预期与实际、首次出现的时间/镜号、受影响区间、最近一个合格点、是否持续、是否传给下游、用户指出的硬条件和证据位置。看整段后再放大问题区间；快动作、换脸、接缝前后加密检查。

以请求/版本证据区分：根图已经错；图正确但绑定丢失/标签错/状态矛盾；请求合理但该候选随机失败；能力/模式不适合；动作负载与时长不匹配；上游替换后引用旧尾帧；视频合格而剪辑/声音错误。

看不到依据时保持根因“假设”，不要将“可能因为多图”写成已确定原因。发现绑定或版本错误先修输入工程，再评估模型；没有系统仓库时提交可核验的修改建议，不声称代码已修。

## 3. 分别判严重度、范围和修法

使用协议的A/B/C严重度与local/shot/root_or_chain范围。大、小偏离是选择修复范围的方法，不是仅按画面差异百分比。

| 判断 | 必要条件 | 下一步 |
|---|---|---|
| 可接受 | 不破坏身份、故事、空间或用户硬条件 | 记录偏差，保留素材 |
| 小偏离 | 根依据正确，核心内容能保留，缺陷可界定 | 选择最小有效修补，局部A也须修 |
| 大偏离 | 根帧/身份/场景/因果错误，持续漂移或局部修补不可行 | 从最早坏点重建必要范围 |
| 未确认 | 帧、请求或版本证据缺失/相互冲突 | 补证据，暂停有关分支，其他工作继续 |

半秒换脸不能被全镜平均分掩盖；整镜轻微偏色也不必自动重建根帧。错误首图不能靠增加“保持身份”把第0帧同时变成另一张正确图。

## 4. 为每问题写 RepairTicket

明确 `basis / root_evidence / severity / scope / frozen_assets / allowed_changes / candidate_route / acceptance / dependency_effects / status`。先写具体假设和所选动作，完成后才写结果。

生产修复可以同时改变必要的输入、时长和路径，但不得将它描述为已识别单变量因果；需要沉淀因果经验时单独做可对照实验。选择以通过硬条件及保留好素材为目标，不机械执行“换种子→改词→编辑→重生”。无seed能力时同参数重试是新随机候选，不称换种子。

## 5. 小偏离：按问题选最小修补

**R0 后期处理**：只是可剪掉的空尾、轻微色差、声音跳变、字幕/文字可后期覆盖时，优先剪辑、调色、混音或重做字幕。裁切/遮挡不得隐藏关键叙事对象；内容错误不能用叠化美化成通过。

**R1 同输入再采样**：根图、绑定、路径和动作设计合理，缺陷不稳定时，再生成独立候选。保存原版，不修改故事去配合失败素材。连续同类失败触发诊断，无需机械凑三次。

**R2 针对性重试**：明确缺少一个动作边界、停点、主运镜或必要身份约束时，精简并补准确条件；或缩短无事件空尾、分解不可能动作。不要堆长负面词表。

**R3 原生视频编辑**：已有运动、机位和节奏值得保留，改动确实适合已接通编辑端点时使用。源片实测≤8.7秒，输出最高720p；按能力档独立选择model，不加generation refs或keyframes。API不等于时间遮罩/局部mask，不承诺未指定区域绝不变化。检查整段身份、光线、背景、物理、首尾、时长与声音；有退化就回到未编辑的好版本。

**R4 局部窗口重新生成**：明确区间坏、前后可用边界足以连接时，取合格左右边界和必要上下文，生成≤15秒的修复候选；可以使用首尾帧＋Look、必要的少量内部帧。它是重新生成，不是对原片局部像素无损修改。

窗口重生先检查：两端身份一致、道具/故事状态compatible、运动方向/速度、光线/空间、时长可实现。边界有错则扩范围找合格边界；找不到或修补退化就升级大偏离。精确按实际时间戳截取，不因MP4文件名或stream copy成功就假定边界准确。

**R5 终态偏离而前段可保留**：提前触水/开门/点灯等事件改变因果时，先判断能否剪在事件前且目标成立；否则重生尾段/本镜。需要插曲镜补充因果时保留原目标，剧情变更由用户决定。不能只改ShotPlan让错误结尾变成正确。

## 6. 大偏离：根帧与链条重建

1. 找到最早坏资产/坏状态，禁止它继续进入新的首帧或参考。
2. 读取批准Look、道具、目标Location/Scene State、正确动作起终态；检查参考是否有冲突。
3. 根据问题选择修正/重制根帧、补目标场景依据、解除错误relay、改独立机位或重设计超负载动作，保持许可外的故事和资源版本。
4. 根帧审核后交 `$grok-long-video-create` 重新生成受影响镜头，明确冻结项与必须终态。没有正确首图时不能先硬接再期待修好。
5. 想保留上镜构图又纠正身份时，比较原生首帧＋Look与融合新首帧；原尾帧已是错误身份时，融合改变起点，必须修前镜或承认切镜。
6. 根图正确但中途漂移时，以问题前合格状态设计短单元、稀疏关键帧或局部重生；不能只看新首帧就宣告解决。
7. 正式选定新版本后沿依赖图复核必要下游，没有真实依赖的合格镜头保留。

不能因某镜失败就全片重生成；也不能把同一坏根帧放进每镜，期待更多Look累计“自动修复”。

## 7. 组内再锚定与漂移累积

触发条件看实际风险：远景多镜之后转近景、遮挡后重现、角度/服装状态变化、关键特征丢失、角色变小或动作负载增加。不要设固定“每三镜重置”，不要仅给组首加Look。

原生首帧＋独立Look已接通且尾帧正确时优先比较这条路径；不支持则使用融合新首帧或reference重新建立。纯尾帧参考、首帧输入、融合图分别记录，不能统称“接力”。

用批准母锚纠正身份，不用上一条漂移视频当新母锚。新视频整段检查身份和故事终态；当前链条配方切换有具体理由并复核接缝。

## 8. 接缝修复和桥接

先看两端单独是否合格，是否为用户希望保留的版本。错误端点先修；正常切镜、换场、时间跳跃可保留。

只有两端合格而实际连接影响理解时，比较剪辑入出点、声音桥、重做组首、剧情需要的过渡镜、首尾帧桥接。优先级由叙事用途决定，不是每边界都插一段。

桥接使用选定左片剪辑出点与右片剪辑入点的真实帧，记录时间戳。确认不存在灯状态或人物位移等因果矛盾。检查桥中段，不以两端吻合证明中间无变形。改变入出点会改变时长、动作相位和声音位置，交编排同步时间线；新增桥要计入真实长度。

## 9. 延长链失败与超长片

原生extend源必须合法；15秒以上完整返回片不能无限递交。选短的合格末段上下文或切换首帧＋Look生成。上下文过短可能丢速度与身份，过长可能超接口；按任务测试。

extend返回包含上下文，识别新增区间后只把需要的新内容加入原时间线；不要拼入源片两遍。保存原始已批准前段，复核返回前段是否有可见变化、交界是否停顿和音轨是否跳变。不能声称原生延长能续同一首BGM。

经典extend/editor切换若造成画风退化，回退并使用1.5分段生成。不可用时输出能力缺口，不偷偷切到另一个平台模型。

## 10. 回归、选片与交还

检查原缺陷消失、冻结项未退化、起终态仍正确、相邻接缝能理解、声音/字幕/时长合理、旧版依赖已复核。修复不通过可退回旧候选，保留比较记录。

提供原版/候选同区间、整镜和必要相邻片段，让用户看得出修改代价。推荐不等于选片；正式选定后按OCC写版本、提取新真实末帧、标记stale/needs_review并按拓扑处理。

向 `$grok-video-orchestrate` 返回 `fixed / accepted_with_deviation / blocked / needs_user_decision`，连同可播放素材、回归和依赖清单。仍有问题时指出哪条假设被否定和下一个有意义动作，不继续无解释随机重试。

# 附录A：共享协议

# 共享协议 GLV/1.0 · 配套 skills v0.1

目录：事实层；叙事层级；输入输出；连续性路径；偏离判断；状态和依赖；交接；质检。

## 1. 唯一事实与职责

使用项目原有 canonical、revision/OCC、ownership、锁、receipt 和选片工具；本协议只是便于交接的概念字段，不要求改数据库或建立第二份canonical。字段名按仓库实际映射。没有这些工具的独立测试，用版本化JSON/文件清单模拟，并标注为本地记录。

故事与资源状态取自批准版本；候选中的偶然事件不能自动改写故事。用户“喜欢这个视频”、审核通过、正式选入时间线和最终成片定版是不同动作，分别留证据。

一名Agent也能按顺序加载三个skill；skill不是新Agent，也不是独立运行任务。若系统已有专业Agent，沿正式委派入口交接。不要为加载本套skill增加Agent数量。

## 2. 叙事与生成层级

| 对象 | 定义 | 约束 |
|---|---|---|
| Project | 完整作品与成片目标 | 目标时长、风格、画幅、质量条件 |
| Group | 相对完整的故事段或动作过程 | 不按固定镜头数切组 |
| Shot | 电影语言中的一镜及其叙事作用 | 有起态、终态、镜头和剪辑关系 |
| GenerationUnit | 一次模型生成的片段 | 可覆盖一镜、同镜一部分，或经验证的数个beats |
| Beat | 可观察的动作/叙事变化 | 时间提示是计划，非精确执行保证 |
| CandidateVersion | 一次真实返回的素材版本 | 不等于已选素材 |

默认先规划全片，再选择生成单元；不把每个beat都拆成一次请求，也不把整个Group硬塞进15秒。一个镜头可由多个单元构成；请求里“无切镜”和“多个机位切镜”不能同时成立。

## 4. 连续性路径的固定语义

| route | 真实输入及起点 | 合理用途 |
|---|---|---|
| `independent_t2v` | 文字，自行建立开头 | 新场景、氛围或身份要求低的镜头 |
| `approved_frame_i2v` | 审核图 → image | 已设计好构图/身份的独立镜头 |
| `real_tail_i2v` | 选定父版本真实尾帧 → image | 清晰正确尾帧的同动作继续 |
| `native_first_plus_refs` | 正确尾帧或审核首帧 → image，Look等 → refs | 兼顾起点与身份；须组合能力可用 |
| `fused_new_first` | Look＋场景/尾帧 → 外部新图 → image | 需要重建首图或渠道不支持组合；起点已经改变 |
| `reference_reestablish` | Look等 → refs，自行决定首帧 | 新机位、换场、身份再建立；不声称硬接 |
| `first_last_generate` | 两端图 → image/last_frame | 两端合格且中间可实现的过渡 |
| `timed_keyframe_generate` | 合格内部帧与时间，可含两端/refs | 动作阶段控制；并不证明所有运动都自然 |
| `native_extend` | 选定视频/合法上下文窗口 → video | 同镜继续；返回包含上下文的完整视频 |
| `native_edit` | 选定短视频 → edit端点 | 已有动作值得保留、编辑字段确实可用的改动 |
| `editorial_cut` | 两段各自合格，直接剪辑连接 | 正常电影切镜，不要求邻帧像素相似 |

所有“硬首帧”措辞指provider明确接收了固定首帧条件；它不是实际输出无需检查的保证。原生1.5帧固定的官方语义与输出转码后的可见结果分别记录。

## 5. 大小偏离：严重度与修复范围分开

严重度：`A/blocking`（故事因果、角色身份、关键道具或运动严重错误）；`B/important`（明显风格、运镜、节奏等偏差）；`C/acceptable`（可接受且不影响理解的小瑕疵）。

范围：`local`（只在短区间/单局部）、`shot`（整镜）、`root_or_chain`（根资产或下游链）。别用坏帧比例定义严重度：半秒换脸可以A；整镜轻微偏暖可以B或C。

执行选择：

- **可接受偏差**：质检确认不影响硬条件，记录并保留。
- **小偏离修补**：根依据正确，核心故事、身份、空间和多数素材可保留，有可界定缺陷；选择最小能通过的修法。局部A问题也可能只需局部修补，但必须修到通过。
- **大偏离重建**：根帧/身份依据/场景状态已错、叙事因果错误、全镜持续漂移、动作不可实现，或局部修补无法保住硬条件；从最早错误依据重建必要范围。
- **证据不足**：暂停相关分支，先查原图、真实帧、请求与版本；不能默认全部重生。

## 6. 候选、依赖与 freshness

任务状态建议映射为：`planned → submitted → pending → received → reviewed → candidate_ready`。独立记录 `selected / rejected / accepted_with_deviation`；被替换父版本的子候选用 `needs_review` 或 `stale` 标记。`received`不能直接变`selected`。

每个从视频提取的帧保存：父视频ID和version/hash、解码时间戳、帧索引、最后实际可解码帧/选定剪辑出点、提取工具信息、图像hash、用途。不是目录里叫tail.png的最新文件就可靠。

区分：视频末尾真实帧、剪辑出点帧、另取的末段较清晰帧、模型生成的终态设计图。若改用较早清晰帧，必须同步剪掉原镜后面的内容，或承认产生了一次切镜；不继续宣称从原真实尾帧接续。

正式选片变化后按真实依赖图处理：

| 变化 | 处理 |
|---|---|
| 子镜image来自旧尾帧 | 标 stale，重新判断/生成；旧尾帧不能被覆盖 |
| 仅reference引用旧父版本 | 标 needs_review；看实际关系是否仍可用 |
| 独立切镜、无真实父依赖 | 保留，复核相邻接缝和叙事状态 |
| 时间线/音频依赖被替换区间 | 复核时长、字幕、配音、音乐与同步 |
| 父只是提出新候选，尚未选用 | 不改变正式时间线和子镜依据 |

按拓扑顺序修必要下游；不能看到“上游改了”就全部重生成。并发任务只允许无未决上游依赖的候选；正式写入遵守锁/OCC，过期返回不覆盖新版本。

## 7. SkillHandoff

生成发现偏差交修复；修复需要重建交首次生成；两者都交编排收口。传递同一对象ID和快照，不复制另一套事实。

```json
{
  "schema": "GLV/1.0",
  "from_skill": "grok-long-video-create",
  "to_skill": "grok-video-repair",
  "run_id": "R001",
  "basis_revision": "project-r12",
  "input_refs": ["ShotPlan:U08@1", "Candidate:C08B@1", "Review:QC08B@1"],
  "affected_units": ["U08"],
  "frozen_assets": ["LOOK_A@3", "PROP_LAMP@2"],
  "allowed_changes": ["repair candidate U08; retain story goal"],
  "required_return": ["RepairTicket", "candidate versions", "regression", "dependencies to review"],
  "task_state": "candidate_ready_for_diagnosis"
}
```

在registry按frontmatter名称解析另外两个skill；不要依赖某个本机绝对路径或安装后可能被改名的兄弟文件夹。缺失时保留handoff，指出缺少的skill，继续不依赖它的工作；不能凭空声称已经加载或委派。

## 8. 质量门槛与停止条件

用蓝本15维检查：语义、角色、场景、光照、运动、镜头、画质、连续性、节奏、转场、声音、风格、情绪、主体完整、物理环境。再加故事起终态、参考实际绑定、版本/依赖、全片声音连续性。

观看整段，首帧/中间/末尾抽样辅助定位；快动作、变形点、接缝两侧提高检查密度。自动视觉评分只能筛查，不能以均分覆盖A问题，不能用截图通过代表整段通过。

用三份独立结论：请求合法与成功；制作决策是否合理；视频是否可接受。若只缺用户审美/剧情/正式选片决定，提交可播放、可比较材料，等待该决定；其他可独立完成项继续推进。

连续若干次同类失败触发诊断，不设全项目三次硬上限；诊断实验尽量一次改一个变量，生产级重构可同时改必要条件，但要列清改动，不宣称完成单变量因果验证。

# 附录B：能力档

# Grok 能力档：v0.1 · 核验日 2026-10-02

目录：证据层级；模式与限制；参考绑定；请求示例；渠道降级；声音与恢复。

## 1. 把三种事实分开

- `documented`：官方文件描述支持。本文数值属于这一层，不代表当前账户已接通。
- `user_reported`：用户提供的渠道限制或使用观察；保留来源，待实际请求验证，不自动升级为已接通。
- `adapter_verified`：当前平台/适配器确实编译并发送了该字段，有脱敏请求证据。
- `visually_accepted`：真实视频及用户评审证明它在某个任务范围内可用。

不要用后一层的单例推导所有任务都可靠，也不要用前一层冒充实际生成成功。记录 `provider / endpoint / model_id / adapter_version / checked_at / evidence`。换渠道、换端点、换版本时重新判断；同一渠道内不同模式也可能使用不同模型。

本文针对官方 API 的 `grok-imagine-video-1.5`，不是旧的语言模型 Grok-1.5。官方模型页列有 preview 和日期别名，生产记录保留真实返回的模型标识。引用 [E1]。

## 2. 模式与限制

以下为简要事实摘要；正式请求以当前官方文档和实际 schema 为准。所有与能力有关的 workflow 建议都是本套 skill 的设计判断，须实测。

| 路径 | 核心输入/端点 | 官方边界 | 实际应用边界 |
|---|---|---|---|
| 文生视频 | `/v1/videos/generations`，`prompt` | 1–15s；480p/720p/1080p [E2] | 不假定会返回或暴露内部中间图 |
| 单图图生视频 | `image` | 1.5 可原生1080p；默认随输入比例 [E3] | 明确指定不同画幅可能拉伸原图；先准备目标比例的图 |
| 参考生成 | `reference_images`，可加 `reference_audios` | 图片最多7张、最高720p [E4] | 参考图本身不是首帧；数量上限不是建议填满 |
| 首帧＋参考 | `image`＋参考 | 1.5 支持；归入参考生成 [E3,E4] | 上限720p；不能继续按纯 i2v 的1080p计划 |
| 首尾帧 | `image`＋`last_frame`；也可只给尾帧 | 1.5 支持，可与参考组合 [E4] | 视为参考路径，按720p规划；实际输出仍检查端点 |
| 内部关键帧 | `keyframes: [{image,timestamp_s}]` | 最多4个，严格在(0,duration)内；1/3秒网格；同槽冲突拒绝 [E4] | 显式用合法网格，排序、留运动时间；不与编辑混用 |
| 原生延长 | `/v1/videos/extensions`＋`video` | 源2–15s；新增2–10s；返完整片；最高720p [E5] | 示例模型是经典 `grok-imagine-video`；单独核验1.5可用性 |
| 原生编辑 | `/v1/videos/edits`＋`video` | 源≤8.7s；时长/比例继承；最高720p [E6] | 示例模型同为经典版本；不能假定是逐帧局部遮罩修复 |

延长/编辑使用 MP4 与受支持编码；不发送自定义比例和分辨率字段，编辑不发送自定义时长。延长的 `duration` 指新增部分，不是完整返回片的总时长。[E5,E6]

用户提供“延长源≤50MB”：在查阅的延长指南中未找到这一通用限制，保留为 `user_reported_channel_limit=50MB`，仅在目标渠道核验后用于该渠道；不要混同 Files API 的公开 URL 大小限制。MB/MiB 及上传路径也分别记录。

官方当前说明经典 `grok-imagine-video` 不支持1.5的首尾/内部帧固定与首帧参考组合；不得用经典版本示例给1.5高级生成模式做映射。反过来也不得将1.5高级帧能力塞进经典编辑/延长请求。[E2,E4]

## 3. 图像和声音的引用绑定

无首帧时，第一张参考用 `<IMAGE_0>`；有 `image` 时它占 `<IMAGE_0>`，独立参考从 `<IMAGE_1>` 起。预设声音用 `<AUDIO_0>`、`<AUDIO_1>`、`<AUDIO_2>`。[E4]

建立本地 `ReferenceBinding`，列出角色/道具/场景/风格、资产版本、provider槽位、prompt标签、负责什么以及不负责什么。不能把另一模型的 `<Audio N>`、`@图N` 或1起始编号直接搬来；内部键帧使用时间字段，不猜测未记录的prompt编号。

1.5 普通账户的声音参考是最多3个 `voice_id` 预设嗓音；自有声音文件需要合作方权限。它不能直接等同于任意音频波形复用或背景音乐接续。[E4]

原生生成默认带音轨，静音生成使用已支持的 `generate_audio=false`。[E2] “无音乐”提示词只是内容引导；没有确认专用控制字段时不得虚构 `disable_music`。原生声音实际保留与否由成片检查决定。

## 4. 官方 REST 请求示例

以下均是请求构造示例，不是已执行任务。占位资源必须替换成可用输入，并核验当前账户和适配器。不要把内部 ShotPlan JSON 全部当作 API body。

```json
{
  "model": "grok-imagine-video-1.5",
  "prompt": "Continue the motion from <IMAGE_0>. Keep the identity and outfit of <IMAGE_1>. The otter walks screen-right toward the doorway and stops before opening it. One continuous shot, steady lateral tracking.",
  "image": {"url": "<APPROVED_REAL_TAIL_URL>"},
  "reference_images": [{"url": "<APPROVED_LOOK_URL>"}],
  "duration": 6,
  "resolution": "720p",
  "aspect_ratio": "16:9",
  "generate_audio": false
}
```

这是原生首帧＋Look，不是把尾帧和Look都放进reference数组。若前镜尾帧已经换脸，先修上游或改变剪辑关系，不能靠Look在第0帧同时恢复另一个身份。

```json
{
  "model": "grok-imagine-video-1.5",
  "prompt": "The lantern is lifted gradually, held steady, then placed on the marked shelf. Continuous physically plausible motion between the pinned frames, no cut.",
  "image": {"url": "<APPROVED_START_URL>"},
  "last_frame": {"url": "<APPROVED_END_URL>"},
  "keyframes": [
    {"image": {"url": "<MIDSTATE_1_URL>"}, "timestamp_s": 2.0},
    {"image": {"url": "<MIDSTATE_2_URL>"}, "timestamp_s": 4.0}
  ],
  "reference_images": [{"url": "<APPROVED_LOOK_URL>"}],
  "duration": 6,
  "resolution": "720p",
  "aspect_ratio": "16:9"
}
```

第二例展示合法字段组合，不建议每镜都用两端加两关键帧。先验证各帧身份、场景、尺度和动作能连接，不能用帧固定要求模型实现不可能的运动。Python SDK 的字段名与 REST 不完全相同，例如 `last_frame_url` 和内部帧 `timestamp`；按所用 SDK 当前 schema 转换，不混写。[E4]

## 5. 适配器预检和降级

1. 先列此任务需要的能力，读取 `CapabilityProfile` 和真实编译请求。
2. 检查字段数、模式组合、输入格式、画幅、时长、内部帧时间、标签顺序、源片长度和字节数。
3. 不支持高级组合时显式降级：原生首帧＋Look → 外部生图融合并审核新首帧 → 单图i2v；或按叙事使用正常切镜/reference重新建立。记录连续性语义和分辨率的变化。
4. 不支持延长时选真实尾帧＋Look的分段生成；不支持编辑时选剪辑、局部窗口重生或根帧重建。不能悄悄丢弃字段还报告原路径成功。
5. `seed / fps / negative_prompt` 没有在本次所查官方生成指南中确认可设置；默认 `unverified`，不发送。不支持时记录 `seed=null`，候选按request_id区分；成片帧率属于后期输出，不反填为模型设置。
6. 图像输入官方可用HTTPS、data URI或Files `file_id` [E3,E4]；第三方可能仅URL。优先保存资产字节和来源版本，分发URL可更换；不得用重新绘图代替保真转存。

## 6. 异步任务与声音策略

提交与轮询分开，立即持久化 `request_id`、脱敏body/hash、父资产版本；完成后检查视频文件、流和视觉。生成输出URL可能临时有效，及时收货；能用当前平台持久化能力时保留文件ID。[E2,E7,E8]

声音策略由项目选择：`native_reviewed`（审核后保留原生声音）、`external_master`（统一旁白/对白、配乐、环境轨）、`hybrid`（选择可用原生音效，另做全片声音）。角色声线、台词准确性、音乐连续性单独验收。外部 TTS 或配音不是自动精准唇形同步；根据任务决定独立lip-sync、重生、避开正面说话特写或采用旁白。

# 附录C：修复手册

# 修复手册：大偏离重建与小偏离修补 · v0.1

目录：判据；根因分流；窗口修复；根帧再建立；终态/接缝；修复工单；回归；用户反馈。

本手册是既有实测方法的条件化迁移和新的Grok测试假设，不能视为已在所有Grok渠道验证。来源边界由交付说明记录。

## 1. 不用单一阈值定义大、小

按三个问题选修复范围：**依据还正确吗？主要内容值得保留吗？能找到合格修复边界吗？**

| 例子 | 严重度/范围 | 选择 |
|---|---|---|
| 一瞬间换脸但前后身份正确 | A/local | 必修，可先局部窗口；不自动全片重做 |
| 整镜暖一点且用户接受 | C/shot或B/shot | 记录/调色；不因全镜受影响就大重建 |
| 首图白斑侧别、衣服和灯都错 | A/root_or_chain | 重建根图，再查真实下游依赖 |
| 门提前打开改变下一镜因果 | A或B/尾段 | 可剪在开门前且故事成立则剪，否则修尾段 |
| 同角色远景数镜后近景换脸 | A/当前或链 | 查首次漂移点，重注批准Look，根错误先修 |
| 新组从室外切室内 | 无缺陷 | 正常切镜，无需桥接 |
| 两端单独很好但观众看不懂人物怎么到达 | B/边界 | 比较剪辑或有叙事用途的过渡；桥接只是候选 |

缺陷可小范围修，并不降低它的严重度。多个看似小缺陷共同表明空间/身份依据失效时，升级大偏离。

## 2. 根因分流与反例

| 证据 | 第一动作 | 不要做 |
|---|---|---|
| 正确Look未进编译后请求 | 修binding/引用顺序，重跑受影响任务 | 仅给prompt加“像原角色” |
| 原首帧已经换装 | 按批准Look重建首帧，查下游 | 固定错误首帧又要求第0帧换回正确衣服 |
| source frame来自旧VideoVersion | 纠正正式父依据并检查freshness | 把新tail.png覆盖旧路径掩盖来源 |
| 根图正确，动作中途手崩坏 | 降动作负载/局部窗口/候选重试 | 认为首帧正确就整段合格 |
| 新场景参考实际仍是楼梯 | 补目标Location/Scene State、改binding | 宣称reference模式绝对不能跨空间 |
| 运动被迫过快或空尾太长 | 改单元设计与长度 | 一律缩到最短或一律15秒 |
| prompt写3秒关键事件，没发送keyframes | 当作节奏引导检查，不宣称固定点 | 把文字时间当Provider强约束 |
| 音乐每镜重起而画面很好 | 成片连续音乐/外部声音轨 | 只为BGM重生所有画面 |

## 3. 小偏离窗口修复：可执行步骤

例：一条12秒视频，5.0–5.7秒灯提手短暂融化；4.3秒之前和6.4秒以后灯与角色正确。

1. 先看整个动作，标实际坏区间；4.3和6.4只是示例，合格边界由视频决定。
2. 记录左/右帧所属视频version/hash、实际PTS、解剖侧别、道具状态、手位置、运动方向与光线。
3. 比较3条候选路线：现有备用候选；保留动作的原生编辑；从两端重生修复窗口。原片12秒不能直接发≤8.7秒编辑；如需编辑先精确截成合法片并承认接缝风险。
4. 默认不假定原生编辑有mask。编辑上下文窗口控制受影响范围，但返回中所有区域仍需回归。
5. 重生窗口用首尾条件和批准Look；关键动作需要时先设计一个正确中间帧，别放原片崩坏帧。
6. 选择合理生成时长；若生成长度与替换窗口不同，在可接受的动作速度范围安排剪辑，或改窗口。不能仅拉伸视频导致不自然动作/声音。
7. 在原时间线上保留左边及右边好片段，插入通过的修复内容；按实际PTS处理重复边界、停顿和音频。不要自动丢一帧来“消除重复”，先检查确实重复且丢帧不改变相位。
8. 看修复整个窗口和前后上下文、再看全镜。动作速度、手和灯关系有突变则扩大窗口或重做该动作段；不因两端固定就通过。

窗口两端不能锁定速度或物理过程；必要时用更多上下文、改变运镜或拆一个自然切镜。找不到合格双端时禁止继续局部“补洞”，转根/镜头重建。

## 4. 大偏离根帧重建：可执行步骤

例：原镜水獭变成另一画风、围巾没了、灯形状也错；这些从首图已出现。

1. 标最早坏点为根帧而不是视频随机性，冻结错误图的传播。
2. 原首图仅保留确实正确的构图/位置依据；批准Look负责身份，批准灯图负责道具，目标场景负责环境。
3. 根据当前生图工具选择局部编辑或全图重制；工具不支持多参考时先建立可用首图方案，不虚构参数。
4. 审核身份/侧别/比例、围巾、灯提手与状态、空间布局、动作起态；有阻塞项继续修图。
5. 用通过的根图生成视频，按风险比较纯i2v与首帧＋Look的候选；检查整个运动过程而非只看图。
6. 提供原版与新候选，让用户决定是否正式替换；更新selected后再提取新尾帧。
7. 将旧尾帧首帧子镜标stale；仅reference的子镜复核；独立镜头保留并复核边界。

历史“crop配方有效”可作为试验线索，但不能假定其字段、角色比例或成功率可直接搬到Grok。更不能拿全画面像素裁剪冒充含Look的参考生图。

## 5. 远景转近景：重新注入身份

例：大鹤/水獭连续远景看起来不错，到中近景身份变了。

先判断远景是**身份不可辨认**还是**身份已明确错**。前者可以从正确动作/空间状态进入更强身份条件路径；后者先修最早错误，而不是把错误尾帧带入组合。

候选A：正确尾帧作image、批准Look作独立reference，保持真实起点。

候选B：Look＋尾帧重建中景新首图，审核后i2v，承认重新构图。

候选C：独立reference建立近景，使用电影切镜保故事/动作关系。

同故事目标、母锚与工作规格下比较；如果路径要求不同分辨率/动作长度，记录差异，不把不可比质量直接归因模式。通过后把“适用风险＋选择＋反例”写配方，不设所有近景都必须融合图。

## 6. 终态偏离：不能让候选改写故事

例：要求“接近水面但尚未触水”，视频提前触水。

- 事件前有可用出点且观众理解目标：提议剪掉触水尾段，同步末帧、时间线和下一镜起态。
- 事件是全镜主要动作或剪后叙事不成立：重生动作或尾段，补明确停点与合理时长/终态条件。
- 用户喜欢已有事件并愿意改故事：提供原目标与改动影响供其决定；确认后通过正式入口改变故事/状态，再复核后续。
- 可以插入合理过渡补因果：解释新增镜头的故事作用与时间代价，不为救失败片任意加剧情。

“生成效果很好”“接受提前触水”“正式选入项目”三项不能互相替代。

## 7. 组间接缝：先问为何要接

正常硬切、景别切换、时间/地点变化：保留。接口能插值，不说明影片需要插值。

桥接仅对合格端点、明确修复目标使用；二端人物、道具、时空或灯状态相互矛盾时，先解决矛盾。桥接常用首尾生成，不使用“内部关键帧在0秒和duration秒”冒充端点。

若只是音轨点击/背景音乐断裂，先音频过渡；若动作方向跳变但正常切镜可以重定位，优先重新选入出点/补空间交代；如果缺一段必要动作，设计有故事功能的过渡镜。

桥接成功仍回归两端身份、中间物理、全片节奏与声音。保留原剪辑作为对照，不能默认桥一定更好。

## 9. 修复后的回归清单

| 层 | 必须检查 |
|---|---|
| 缺陷 | 原问题区间与可观察验收条件 |
| 冻结项 | 角色/服装/画风/道具/场景、故事因果 |
| 时间 | 时长、入出点、重复帧、速度、关键事件顺序 |
| 声音 | 台词、音色、背景音、配乐、同步与点击 |
| 相邻镜 | 动作方向/相位、空间、光线、叙事状态 |
| 项目 | 正式选片版本、尾帧来源、freshness/下游、OCC |

没有用户选片的新候选不触发正式下游替换。仅父候选新增不能让正在使用的旧版凭空失效。

## 10. 用户反馈如何变成经验

将反馈记成“对象/版本＋区间＋可观察问题＋用户接受程度”，避免只有“差/好”。系统自行定位和提出比较材料，不要求用户写专业诊断。

成功配方至少保留：改了什么、保持了什么、是否也改了分辨率/时长/参考、失败样本、用户最后选了哪个。多因素变化只证明新组合可用，不能证明其中某一项单独有效。
