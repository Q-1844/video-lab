# Grok 视频诊断与修复

执行版本 v0.1；优先修最早错误依据，保留有价值素材；不承诺生成式编辑保留其他像素或声音。

## 1. 读取证据并冻结合格部分

先读 [共享协议](../references/shared-protocol.md) 与 [能力档](../references/grok-capabilities.md)，再读 [修复手册](../references/repair-playbook.md)。接受ShotPlan、批准锚点、候选/选片版本、用户反馈、实际请求、来源帧和依赖图。

输出RepairTicket、修复前后候选、实际回执、原问题及回归检查、正式选片所需材料、下游复核清单。没有真实视频时只做有条件诊断，列出证据缺口；不能把文字描述推测成亲眼看到的坏帧。

先列 `keep`（合格且应保留）、`repair`（确需处理）、`uncertain`（待补证据）。冻结正确Look、关键道具、故事因果、已选镜头及不依赖坏点的分支；新候选不能覆盖旧版本。

## 2. 找到首个偏离点

沿因果顺序检查：批准资产 → 实际参考绑定 → 根帧 → 首帧 → 运动过程 → 尾态 → 下游起镜 → 时间线/声音。

对每个问题记录：预期与实际、首次出现的时间/镜号、受影响区间、最近一个合格点、是否持续、是否传给下游、用户指出的硬条件和证据位置。看整段后再放大问题区间；快动作、换脸、接缝前后加密检查。

以请求/版本证据区分：根图已经错；图正确但绑定丢失/标签错/状态矛盾；请求合理但该候选随机失败；能力/模式不适合；动作负载与时长不匹配；上游替换后引用旧尾帧；视频合格而剪辑/声音错误。

看不到依据时保持根因“假设”，不要将“可能因为多图”写成已确定原因。发现绑定或版本错误先修输入工程，再评估模型；没有系统仓库时提交可核验的修改建议，不声称代码已修。

## 3. 分别判严重度、范围和修法

使用协议的A/B/C严重度与local/shot/root_or_chain范围。大、小偏离是选择修复范围的方法，不是仅按画面差异百分比。

| 判断 | 必要条件 | 下一步 |
|---|---|---|
| 可接受 | 不破坏身份、故事、空间或用户硬条件 | 记录偏差，保留素材 |
| 小偏离 | 根依据正确，核心内容能保留，缺陷可界定 | 选择最小有效修补，局部A也须修 |
| 大偏离 | 根帧/身份/场景/因果错误，持续漂移或局部修补不可行 | 从最早坏点重建必要范围 |
| 未确认 | 帧、请求或版本证据缺失/相互冲突 | 补证据，暂停有关分支，其他工作继续 |

半秒换脸不能被全镜平均分掩盖；整镜轻微偏色也不必自动重建根帧。错误首图不能靠增加“保持身份”把第0帧同时变成另一张正确图。

## 4. 为每问题写 RepairTicket

明确 `basis / root_evidence / severity / scope / frozen_assets / allowed_changes / candidate_route / acceptance / dependency_effects / status`。先写具体假设和所选动作，完成后才写结果。

生产修复可以同时改变必要的输入、时长和路径，但不得将它描述为已识别单变量因果；需要沉淀因果经验时单独做可对照实验。选择以通过硬条件及保留好素材为目标，不机械执行“换种子→改词→编辑→重生”。无seed能力时同参数重试是新随机候选，不称换种子。

## 5. 小偏离：按问题选最小修补

**R0 后期处理**：只是可剪掉的空尾、轻微色差、声音跳变、字幕/文字可后期覆盖时，优先剪辑、调色、混音或重做字幕。裁切/遮挡不得隐藏关键叙事对象；内容错误不能用叠化美化成通过。

**R1 同输入再采样**：根图、绑定、路径和动作设计合理，缺陷不稳定时，再生成独立候选。保存原版，不修改故事去配合失败素材。连续同类失败触发诊断，无需机械凑三次。

**R2 针对性重试**：明确缺少一个动作边界、停点、主运镜或必要身份约束时，精简并补准确条件；或缩短无事件空尾、分解不可能动作。不要堆长负面词表。

**R3 原生视频编辑**：已有运动、机位和节奏值得保留，改动确实适合已接通编辑端点时使用。源片实测≤8.7秒，输出最高720p；按能力档独立选择model，不加generation refs或keyframes。API不等于时间遮罩/局部mask，不承诺未指定区域绝不变化。检查整段身份、光线、背景、物理、首尾、时长与声音；有退化就回到未编辑的好版本。

**R4 局部窗口重新生成**：明确区间坏、前后可用边界足以连接时，取合格左右边界和必要上下文，生成≤15秒的修复候选；可以使用首尾帧＋Look、必要的少量内部帧。它是重新生成，不是对原片局部像素无损修改。

窗口重生先检查：两端身份一致、道具/故事状态compatible、运动方向/速度、光线/空间、时长可实现。边界有错则扩范围找合格边界；找不到或修补退化就升级大偏离。精确按实际时间戳截取，不因MP4文件名或stream copy成功就假定边界准确。

**R5 终态偏离而前段可保留**：提前触水/开门/点灯等事件改变因果时，先判断能否剪在事件前且目标成立；否则重生尾段/本镜。需要插曲镜补充因果时保留原目标，剧情变更由用户决定。不能只改ShotPlan让错误结尾变成正确。

## 6. 大偏离：根帧与链条重建

1. 找到最早坏资产/坏状态，禁止它继续进入新的首帧或参考。
2. 读取批准Look、道具、目标Location/Scene State、正确动作起终态；检查参考是否有冲突。
3. 根据问题选择修正/重制根帧、补目标场景依据、解除错误relay、改独立机位或重设计超负载动作，保持许可外的故事和资源版本。
4. 根帧审核后交 `$grok-long-video-create` 重新生成受影响镜头，明确冻结项与必须终态。没有正确首图时不能先硬接再期待修好。
5. 想保留上镜构图又纠正身份时，比较原生首帧＋Look与融合新首帧；原尾帧已是错误身份时，融合改变起点，必须修前镜或承认切镜。
6. 根图正确但中途漂移时，以问题前合格状态设计短单元、稀疏关键帧或局部重生；不能只看新首帧就宣告解决。
7. 正式选定新版本后沿依赖图复核必要下游，没有真实依赖的合格镜头保留。

不能因某镜失败就全片重生成；也不能把同一坏根帧放进每镜，期待更多Look累计“自动修复”。

## 7. 组内再锚定与漂移累积

触发条件看实际风险：远景多镜之后转近景、遮挡后重现、角度/服装状态变化、关键特征丢失、角色变小或动作负载增加。不要设固定“每三镜重置”，不要仅给组首加Look。

原生首帧＋独立Look已接通且尾帧正确时优先比较这条路径；不支持则使用融合新首帧或reference重新建立。纯尾帧参考、首帧输入、融合图分别记录，不能统称“接力”。

用批准母锚纠正身份，不用上一条漂移视频当新母锚。新视频整段检查身份和故事终态；当前链条配方切换有具体理由并复核接缝。

## 8. 接缝修复和桥接

先看两端单独是否合格，是否为用户希望保留的版本。错误端点先修；正常切镜、换场、时间跳跃可保留。

只有两端合格而实际连接影响理解时，比较剪辑入出点、声音桥、重做组首、剧情需要的过渡镜、首尾帧桥接。优先级由叙事用途决定，不是每边界都插一段。

桥接使用选定左片剪辑出点与右片剪辑入点的真实帧，记录时间戳。确认不存在灯状态或人物位移等因果矛盾。检查桥中段，不以两端吻合证明中间无变形。改变入出点会改变时长、动作相位和声音位置，交编排同步时间线；新增桥要计入真实长度。

## 9. 延长链失败与超长片

原生extend源必须合法；15秒以上完整返回片不能无限递交。选短的合格末段上下文或切换首帧＋Look生成。上下文过短可能丢速度与身份，过长可能超接口；按任务测试。

extend返回包含上下文，识别新增区间后只把需要的新内容加入原时间线；不要拼入源片两遍。保存原始已批准前段，复核返回前段是否有可见变化、交界是否停顿和音轨是否跳变。不能声称原生延长能续同一首BGM。

经典extend/editor切换若造成画风退化，回退并使用1.5分段生成。不可用时输出能力缺口，不偷偷切到另一个平台模型。

## 10. 回归、选片与交还

检查原缺陷消失、冻结项未退化、起终态仍正确、相邻接缝能理解、声音/字幕/时长合理、旧版依赖已复核。修复不通过可退回旧候选，保留比较记录。

提供原版/候选同区间、整镜和必要相邻片段，让用户看得出修改代价。推荐不等于选片；正式选定后按OCC写版本、提取新真实末帧、标记stale/needs_review并按拓扑处理。

向 `$grok-video-orchestrate` 返回 `fixed / accepted_with_deviation / blocked / needs_user_decision`，连同可播放素材、回归和依赖清单。仍有问题时指出哪条假设被否定和下一个有意义动作，不继续无解释随机重试。
